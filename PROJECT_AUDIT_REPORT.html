A. Tổng quan kiến trúc & stack

Kiến trúc

  • SPA React nằm tại quan tri, điều hướng theo role ADMIN / ACCOUNTANT / EMPLOYEE.
  • REST API Spring Boot tại backendqt/backendqt, kiến trúc controller - service - repository - entity - DTO.
  • PostgreSQL qua Spring Data JPA; MinIO lưu tệp; JWT stateless; AI provider Ollama hoặc cloud qua cấu hình.

Điểm tích cực xác nhận

  • API client tập trung có Bearer interceptor và logout khi 401.
  • Frontend gọi /api/v1/users/me sau khi có token để đồng bộ user.
  • Controller nhạy cảm đã có @PreAuthorize; Document/Invoice service áp phạm vi owner cho employee.

Nguồn: pom.xml, quan tri/package.json, SecurityConfig.java, DocumentService.java, App.tsx.

B. Cấu trúc project

Frontend

  • src/App.tsx: route guards và layouts theo role.
  • src/pages/{admin,accountant,employee}: các màn hình nghiệp vụ.
  • src/services: API axios, auth, document, invoice, classification, role, dashboard, AI.
  • src/components: sidebar/layout/topbar/stat card/status badge.

Backend

  • controller: auth, user/role/permission, document/invoice/classification, dashboard, AI.
  • service: nghiệp vụ, mapper, storage và workflow.
  • security: JWT service/filter và UserDetailsService.
  • entity/repository/dto: persistence, response/request contract.
  • resources: YAML và migration SQL.
Phát hiện cấu trúc cần dọn dẹp
  • quan tri/src/main.ts, counter.ts, assets Vite và mockData.ts/.js là artefact/nhánh cũ; entry runtime là main.tsx.
  • pages/Dashboard.tsx, Documents.tsx, DocumentDetail.tsx, UserManagement.tsx nằm ngoài route hiện hành; các bản theo role mới được import trong App.tsx.
  • Hai lớp role cùng tồn tại: enum legacy User.role và bảng role assignment. Code có đồng bộ một phần, nhưng custom role có thể không map vào enum.

D. UI/UX audit

Điểm tốt

  • Phân layout/sidebar rõ theo role, navigation nhất quán và dùng Lucide icons.
  • Các trang document/dashboard có loading, empty và error state cơ bản.
  • Tailwind utility nhất quán, grid có breakpoint tại nhiều màn hình.

Cần ưu tiên

  • Sidebar không thấy cơ chế thu gọn/drawer cho mobile; cần kiểm tra thực tế ở viewport hẹp.
  • Bảng document/statistics cần wrapper cuộn ngang và tiêu đề sticky/đọc được trên màn hình nhỏ.
  • SystemStatistics.tsx dùng số liệu và chart giả nhưng bề ngoài giống dữ liệu thật, gây hiểu nhầm nghiệp vụ.
  • Chưa thấy test accessibility hoặc ErrorBoundary; cần audit keyboard/focus/contrast bằng trình duyệt.

Login, Register; AdminDashboard, UserManagement, RoleManagement, SystemStatistics; AccountantDashboard, AccountantDocuments, AccountantDocumentDetail, AccountantUpload, AiTest; EmployeeDashboard; các layout/sidebar/topbar dùng chung. E. Code quality & architecture

  • Tốt: backend phân tầng hợp lý; DTO validation, global exception handler, transaction annotation và repository query theo ownership đã xuất hiện.
  • Rủi ro: kiểm tra quyền đang phân tán giữa controller, SecurityConfig và service; sự song song role enum/bảng role làm tăng khả năng lệch quyền.
  • Rủi ro: frontend còn duplicate các màn dashboard/document detail theo role; một số file starter/legacy tăng nhiễu và chi phí bảo trì.
  • Thiếu: frontend không có script test hoặc lint trong package manifest; backend chỉ có một test integration class.
  • Logging: lỗi xóa object MinIO bị nuốt trong DocumentService.delete, khiến orphan file khó truy vết.

F. Performance audit

  • Danh sách document/invoice dùng findAll() và không thấy pagination/filter server-side: rủi ro tải toàn bộ dữ liệu khi tăng quy mô.
  • Không thấy route-level lazy import React, khiến bundle tải toàn bộ các màn admin/accountant ngay từ entry.
  • Upload document stream lên MinIO, nhưng không có giới hạn tổng kích thước tệp trong service/controller hoặc policy multipart rõ ràng.
  • Dashboard/role screens gọi API khi mount; không thấy cache/invalidation layer. Quy mô hiện tại chấp nhận được, nhưng cần React Query/SWR hoặc cache HTTP khi dữ liệu tăng.
  • Không đánh giá bundle/runtime thực tế vì không chạy build theo ràng buộc “chỉ tạo report”.

I-J. Thiếu, chưa hoàn thiện & rủi ro logic

Thiếu / chưa hoàn thiện

  • Policy upload, scanning và giới hạn multipart.
  • Pagination, filtering và sorting API cho danh sách lớn.
  • API-driven system statistics thay cho mock/hard-code.
  • Frontend test, lint, accessibility audit, ErrorBoundary.
  • Production profile an toàn, secrets rotation và deployment checks.

Rủi ro cần theo dõi

  • Admin/accountant có quyền đọc toàn bộ documents/invoices; xác nhận đây là policy công ty mong muốn.
  • Xóa document nuốt lỗi MinIO; DB có thể xóa nhưng object còn tồn tại.
  • Version number tính bằng max+1 có thể race khi hai upload cùng document.
  • Endpoint /api/v1/users/me thiếu annotation explicit như các endpoint cùng controller, dù SecurityConfig vẫn yêu cầu authenticated.
  • File cũ pages/UserManagement.tsx gọi localhost:8080/api/users, khác base URL/prefix hiện tại; tránh vô tình import lại.
